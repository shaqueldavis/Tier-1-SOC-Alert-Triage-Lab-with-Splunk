# Varify Logs Reach Dashboard.md

Open PowerShell as an administrator if you haven't already on the Windows VM.

Get the Windows VM's hostname:
```powershell
$env:COMPUTERNAME
```

This value will normally become the Splunk host field for events coming from the Windows VM endpoint.

Before checking Splunk, let's make sure each log source actually contains data.
```powershell
Get-WinEvent -LogName Security -MaxEvents 5
```
```powershell
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 5
```
```powershell
Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational" -MaxEvents 5
```

As long as these commands return events, Windows has telemetry available for the Universal Forwarder to collect.

Discover exactly what Windows log sources Splunk sees. search for:
```
index=* host="<WINDOWS-HOSTNAME>" | stats count by source sourcetype
```

Under "sourcetype" you should see:
```
XmlWinEventLog:Security
XmlWinEventLog:Microsoft-Windows-PowerShell/Operational
XmlWinEventLog:Microsoft-Windows-Sysmon/Operational
```

<img width="2480" height="1374" alt="image" src="https://github.com/user-attachments/assets/7f43d264-079e-447b-8101-713a2cd148fb" />

In my screenshot we see that `XmlWinEventLog:Microsoft-Windows-Sysmon/Operational` is missing. Which means Splunk may not be seeing my Sysmon logs.

So now we need to troubleshoot.

After doing a number of checks and verifications I found that it may be a permissions issue.

Check what account the Splunk Forwarder runs as:
```powershell
Get-CimInstance Win32_Service -Filter "Name='SplunkForwarder'" | Select-Object Name, StartName, State
```

<img width="2448" height="338" alt="image" src="https://github.com/user-attachments/assets/707820ae-c999-455c-a4a8-83cbb0bca09f" />

<br>
<br>
<br>
<br>

`NT SERVICE\SplunkForwarder` is the important clue. If instead we saw `LocalSystem` then permissions would be less likely the potential issue.

`NT SERVICE\SplunkForwarder` means our Universal Forwarder is running under Splunk’s least-privileged virtual service account, not `LocalSystem`.

Since Security and PowerShell logs are working but Sysmon is not, the next clean step is to give that account permission to read Windows event logs.

Add the service account to Event Log Readers:
```powershell
net localgroup "Event Log Readers" "NT SERVICE\SplunkForwarder" /add
```

You should see:

The command completed successfully.

Restart-Service SplunkForwarder

Generate a fresh Sysmon event by opening notepad:
```powershell
notepad.exe
```

Close it out after you open it.

Confirm Sysmon recorded it:
```powershell
Get-WinEvent -FilterHashtable @{
    LogName='Microsoft-Windows-Sysmon/Operational'
    Id=1
} -MaxEvents 3
```

You should see a recent Event ID 1.
