# Start up Splunk Enterprise

### Start Splunk for the first time

Within a ssh session from your Windows client to your Ubuntu server, start splunk:
```bash
sudo -H -u splunk /opt/splunk/bin/splunk start --accept-license
```

You will be met with a few prompts.
- Enter the password you set during instillation.
- Set up a username for your Splunk Enterprise administrator account.
- Set up a password for your Splunk Enterprise administrator account and confirm it.

### Troubleshoot hostname resolution

In our case this step is essentially optional, but worth including.

As I mentioned above using `http://<Ubuntu-IP>:8000` will bypass hostname resolution and take you directly to your Splunk interface, as seen in the image below.

<img width="2473" height="1376" alt="image" src="https://github.com/user-attachments/assets/7a1fb217-c5cb-40b4-aeb3-18d299188ae8" />

<br>
<br>
<br>
<br>

However, if you use the exact URL that was provided for you in the output `http://<Host-Name>:8000` you will get an error.

<img width="2479" height="1376" alt="image" src="https://github.com/user-attachments/assets/47327e56-45a0-477d-b6b2-f7874a0afe8c" />

<br>
<br>
<br>
<br>

`http://splunk-server:8000` is failing because our Windows VM does not currently know that splunk-server = 192.168.113.159, or in other words, `<Host-Name>` = `<IP-Address>`. This is a a hostname-resolution issue.

From an administrator PowerShell window, open the "hosts" file:
```powershell
notepad "C:\Windows\System32\drivers\etc\hosts"
```

Add this line to the bottom of the file:
```
<Ubuntu-IP>    <Ubuntu-Host-Name> 
```

Make sure to put your Ubuntu IP address and host name. In my case:
```
192.168.113.159    splunk-server
```

Save the file and exit.

<img width="1831" height="995" alt="image" src="https://github.com/user-attachments/assets/2a258ec1-4069-4c20-9ce6-ce1ebc080026" />

<br>
<br>
<br>
<br>

Reset the DNS resolver:
```powershell
ipconfig /flushdns
```

<img width="919" height="213" alt="image" src="https://github.com/user-attachments/assets/5d7746a5-3813-40fd-8e0c-56b6b7ae2b11" />

<br>
<br>
<br>
<br>

Quickly check the status. Ping you Ubuntu server by it's host name:
```powershell
ping <Host-Name>
```
In my case:
```powershell
ping splunk-server
```

<img width="1278" height="418" alt="image" src="https://github.com/user-attachments/assets/6f1d9d76-4afb-4fe9-affa-666b82332394" />

<br>
<br>
<br>
<br>

Now if you visit the website using your host name it should work the same as when using your IP address.

### Configure Splunk to receive forwarded data

Return to the administrator PowerShell window.

Configure Splunk Enterprise to listen for Splunk Universal Forwarder traffic on TCP port 9997
```bash
sudo -H -u splunk /opt/splunk/bin/splunk enable listen 9997
```

- Enter your Ubuntu server password
- Enter the Splunk enterprise administrator user username you just created
- Enter the Splunk Enterprise administrator user password you just created

<img width="2442" height="276" alt="image" src="https://github.com/user-attachments/assets/1a8a1cec-924e-445d-bc0d-ede747e7ccb7" />

<br>
<br>
<br>
<br>

Splunk requires a restart after enabling the receiver.
```bash
sudo -H -u splunk /opt/splunk/bin/splunk restart
```

This may take a while.

<img width="1728" height="162" alt="image" src="https://github.com/user-attachments/assets/4e266293-cebd-4660-bb90-336d6db9d3ab" />

<br>
<br>
<br>
<br>

Check the status to confirm its running:
```bash
sudo -H -u splunk /opt/splunk/bin/splunk status
```

You should see "splunk is running".

<img width="1571" height="149" alt="image" src="https://github.com/user-attachments/assets/f0914e13-fa8c-4d23-a625-d54535922556" />

<br>
<br>
<br>
<br>

Verify Ubuntu is listening on port 9997:
```bash
sudo ss -ltnp | grep 9997
```

You should see something along the lines of: `LISTEN 0      128          0.0.0.0:9997`.

<img width="1893" height="112" alt="image" src="https://github.com/user-attachments/assets/e408ccec-7eb2-4316-b789-6c5c9753af6f" />

<br>
<br>
<br>
<br>

Allow the forwarding port with UFW.
```bash
sudo ufw allow 9997/tcp
```

Splunk server may be listening on: TCP 9997 but if UFW is active and does not allow that port, incoming traffic from the Windows Universal Forwarder can be dropped by the Ubuntu firewall.

<img width="1098" height="153" alt="image" src="https://github.com/user-attachments/assets/278b0e06-f93a-496e-84a3-a93e51db9ff1" />

<br>
<br>
<br>
<br>

Now switch to Windows by opening another PowerShell window as an administrator and test the network connection

First test whether Windows can reach the Ubuntu server on port 9997:
```powershell
Test-NetConnection <Ubuntu-IP> -Port 9997
```
In my case
```powershell
Test-NetConnection 192.168.113.159 -Port 9997
```

You should see `TcpTestSucceeded : True`.
