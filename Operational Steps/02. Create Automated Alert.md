Here is the SPL we created in the last phase. 
```spl
index=* sourcetype="XmlWinEventLog:Security" "<EventID>4625</EventID>"
| bin _time span=10m
| stats count as failed_logins by _time host
| where failed_logins >= 5
```

Now we will turn it into an automated alert.

With the SPL in the search bar, click `Save As` → `Alert`.

Set Title to "Repeat Failed Login Attempts".

Set Description to "5 or more failed logins within 10 minutes or less".

Keep Permissions as "Private".
- This is because we are testing the alert for lab purposes.
- "Shared in App" would be used in a more realistic multi-analyst SOC environment where we want everyone using the Search & Reporting app to have access to the detection.
 
Keep Alert type as "Scheduled". 
- Set it to "Run on Cron Schedule".
    
For Time Range click the box that says, "Last 15 minutes", choose the "Advanced" tab, and set it to "Earliest: `-10m`", and "Latest: `now`". Then chose "Apply".
  
Set the Cron Expression to:
```cron
*/5 * * * *
```
- `*/5 * * * *` means run every 5 minutes
    
Set Expires to "365 days(s)". This alert will continue running on its */5 * * * * schedule until that date. After it expires, Splunk stops running that alert.

Keep the alert as trigger whenever the number of results is greater than 0. 

Set Trigger to "For each result".

Check the box next to  "Throttle". 

Leave Suppress results containing field value empty.

Set Suppress triggering for to 10 minutes.
- because the alert scans every 5 minutes for the last 10 minutes, we keep the alert from triggering for the same instance twice within that 10 minute window.

Under Trigger Actions choose Add Actions → Add to Triggered Alerts. Set the severity to "Midum"
